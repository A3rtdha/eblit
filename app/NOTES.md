# Eblit — договорённости UI

Не выкидывать и не «улучшать» в обход этого файла.

## Сервисы и статусы

Три иконки внизу слева — дашборд состояния подключения.

| Иконка | Сервис | Что значит ok / bad |
|---|---|---|
| куб | sing-box / TUN | процесс жив, адаптер `tun-fastly` на месте |
| облако | WARP | SOCKS `:40000` отвечает |
| пин | сервер Lagom | текущий выход отвечает |

Цвета уже есть в CSS: `off` / `ok` / `bad`.

Пока питание **включено**, софт сам проверяет сервисы по таймеру (интервал с «Проб»). Лёгкий зонд (`light_tick`), не полная проверка. Упал — иконка краснеет. Обрыв чинит **watchdog** (см. ниже).

Пока питание **выключено** — все три `off`.

## Галочка (Проверка)

Не watchdog и не автопочинка. Форс-прогон тех же сервисов **сейчас**.

Тот же смысл, что был у `test.bat` (`app.stack.probe.full_test`):

1. WARP SOCKS `:40000` → Spotify
2. Spotify через TUN
3. эндпоинт Firefox VPN
4. есть ли `tun-fastly`
5. Grok через Lagom `:2080`
6. Cursor через Lagom
7. последняя строка `health.log`

Старт и перезапуск гоняют полную проверку в конце сами. Подключение — Python (`app.stack`), не bat/vbs. UAC на start/stop/reload/teredo (автозапуск — без).

**Стоп требует админа.** `sing-box` поднят из-под админа, поэтому `taskkill` из обычного процесса молча получает «отказано в доступе». `lifecycle.stop` проверяет `singbox.wait_gone()` и, если процесс жив, возвращает `power: True` + `why` и **не рвёт WARP** (иначе подключение остаётся с мёртвым SOCKS). Кнопка питания и `--stack stop` поднимают UAC.

**Кнопка не врёт.** Клик не переключает подпись сразу: `Включаю…` / `Выключаю…` / `Перезапуск…` / `Проверяю…`, ринг питания медленно пульсирует, остров кнопок заблокирован. `Включено` появляется только с ответом подключения (WARP + TUN — это секунды). Состояние снимается ответом с ключом `power`, а если подключение молчит и не занято — сторожевой таймер в `armPull`. Пока нет `_busy`, `sync_power` раз в 5 с сверяет подпись с `singbox.running()`: живой сирота (start.bat, прошлый сеанс) больше не оставляет «Выключено». Tick по-прежнему **без** `power` — иначе мигнет off посреди старта.

Сетап (`python -m app.setup` / `EblitSetup.exe`): свежий WARP MSI (код 3010 = успех) + ждать демон `CloudflareWARP`/`warp-svc`, не только `--version` + `registration new` если пусто (есть fallback `register`) + disconnect, затем MASQUE/proxy `:40000` (есть fallback `set-mode` / `set-proxy-port`) + `connect` (таймаут `:40000` установку не валит — дожмёт Eblit). Свежий sing-box, копия в `%ProgramFiles%\Eblit`, Teredo off, WebView2 если нет. WARP при uninstall Eblit не снимать. Старт стека сам регистрирует и рвёт WARP, если SOCKS `:40000` не поднялся — иначе GUI «Выключено», а клиент Cloudflare ещё в туннеле. Окно Cloudflare WARP по питанию и при открытии Eblit **не** поднимаем — только `warp-cli`. Из elevated setup GUI не запускать — окно уедет в сессию админа. Окно установки — те же чернила, что у Eblit (`app/setup/ui.py`): сразу «Идёт установка» под названием (иначе окно выглядит как «ничего не происходит»), шаги точками, тонкая live-полоса, без галочек-мастера. `_place` и тёмная шапка вызываются до mainloop, иначе окно обрезается и выглядит чужим.

Автозапуск окна — `HKCU\...\Run\Eblit` (сам exe, без `--stack`). Старый schtasks `Eblit` / `ZapretFastlySplit` при вкл/выкл снимаем. Жёлтая точка: галочка «в трей» → hide, снята → minimize.

Успешный старт пишет `eblit-power.json` `{"on": true}`, успешный стоп — `{"on": false}`. Фейл старта файл не ставит в on; выход без стопа файл не трогает. При открытии окна после `status()`: файл on и sing-box мёртв → тот же `start()` (UAC как вручную). Живой сирота — второй старт не зовём. «Сразу после включения ПК» работает только если стоит «Запускать вместе с Windows»; иначе — при следующем открытии окна. На логине будет один UAC. Файл не в payload и установщик его не затирает.

## Watchdog — сам чинит обрыв

Отдельный демон-поток в `Bridge` (`_watchdog`), стартует в `set_window`, живёт независимо от окна — работает и свёрнутым в трей. Раньше здесь было жёсткое «подключение само не перезапускаем»; сняли по прямому запросу: у юзера отваливалось, а прила молчала.

Логика (`_watchdog_step`, константы `WD_*`): пока `_want_on` (юзер включил, или стек уже жил при открытии окна) и тумблер «Сам переподключаться» вкл, раз в 15с гоняет `light_tick`. Если процесс умер — `light_tick` не зовём, это и так обрыв. `WD_DEBOUNCE` (2) фейла подряд → OS-уведомка через трей (`pystray.notify`, колбэк ставит `__main__` → `set_notify`) + `_job(self._reload)`. Кулдаун 90с между попытками, максимум `WD_MAX_ATTEMPTS` (3), потом «включите вручную» и долгий бэк-офф. Восстановилось — счётчики в ноль + уведомка. Стоп снимает `_want_on`, иначе сторож поднимал бы стек обратно.

Не дёргается во время ручной операции (`_busy`) и при выключенном питании. Тумблер — `set_autoreconnect`, состояние в памяти + localStorage `eblit-reconnect`, JS шлёт при старте и смене.

**UAC:** `_reload` из-под неповышенного GUI поднимает админа (`admin.elevated`), т.е. авто-переподключение даёт запрос UAC. Иначе никак — kill sing-box (он под админом) и подъём TUN требуют прав. Тумблером можно выключить.

## Трей — в том же процессе

Один процесс: окно + трей (`app/tray.py`, поток `eblit-tray`). Флага `--tray` и `app/tray_host.py` больше нет.

Раньше трей поднимался вторым процессом. Зависание давал публичный `Bridge.window` — pywebview рекурсивно обходил js_api (см. ниже).

Правила, чтобы не вернуть зависание:

- Из потока трея окно трогаем **только Win32** (`ShowWindow`, `PostMessage`), не `window.show()` / `evaluate_js` — это pythonnet-маршалинг в GUI-поток.
- Ищем окно своего процесса (`own_hwnd`), а не первое с заголовком `Eblit`: иначе вторая копия перехватит.
- Трей не критичен: не поднялся — пишем в лог и живём дальше с окном.
- `msedgewebview2.exe` рядом в диспетчере — это рендерер WebView2, не наш процесс.

## Окно (pywebview) — грабли

- **У `Bridge` публичными могут быть только методы.** pywebview рекурсивно обходит `js_api` (`webview/util.py`, `get_functions`) и лезет в любой публичный не-callable атрибут. Публичный `window` увёл обход в `window.native.AccessibilityObject.Bounds.Empty…` — `maximum recursion depth exceeded` и ~15–30 с «не отвечает» на UI-потоке. Окно живёт в `_window`, ставится через `set_window`.
- **Ничего не звать в UI-поток из воркера.** `window.move()` из `events.shown` (а событие у pywebview фоновое) и `evaluate_js` из фонового потока вешали окно наглухо. Результат кладём в `Bridge._push`, JS сам забирает через `pull()`.
- **`easy_drag` тянет окно за любое место** — pywebview слушает `mousedown` на `window`. Поэтому текст выделяется только в `input` / `textarea` (`user-select`), а `mousedown` в полях не всплывает до `window` (`app.js`), иначе выделение мышью в поле съедалось перетаскиванием окна.
- **Центровка при создании.** У frameless `CenterScreen` сбивается снятием рамки, поэтому `x`/`y` считаем сами (`app/place.py`) по рабочей области монитора под курсором. `move()` после показа — нельзя.
- `status()` и лёгкая проверка не ждут сеть: питание отвечает сразу, сервисы догоняют.

## Куда выводить результат

- **Не** MessageBox, **не** второе окно, **не** панель лога на стекле.
- Результат = те же три иконки.
- Наведение / тап по иконке — коротко почему (`WARP :40000 молчит`, `tun-fastly нет`, `сервер timeout`).
- Сырой прогон — в файл (`split-ui.log`, `health.log`).

## Маршрут (узкий TUN)

В sing-box попадает только то, что нужно Eblit:

| Трафик | Куда |
|---|---|
| Fastly-CIDR | WARP SOCKS `:40000` |
| Lagom-суффиксы | fake-ip `198.18.0.0/15` → LagomVPN |
| Всё остальное | мимо TUN (Ethernet / zapret) |

`inbounds[tun-fastly].route_address` = Fastly-CIDR + `198.18.0.0/15` + DNS `8.8.8.8` / `1.1.1.1`. Полного `auto_route` на весь интернет нет.

WARP-клиент в режиме proxy `:40000`; split-tunnel WARP на игры не действует — игры просто не попадают в TUN.

Discord / Google / Gemini / игры не проксируются sing-box. Discord — ethernet/zapret.

Meta / Quest (`oculus.com`, `oculuscdn.com`, `oculusvr.com`, `meta.com`, `facebook.com`, `facebook-hardware.com`, `fbcdn.net`, `fbsbx.com`, `instagram.com`, `cdninstagram.com`) — Lagom-суффиксы. `www.google.com` из списка Meta **не добавлять**: им шлем проверяет доступность сети, и Google в Lagom не идёт.

DoH в браузере режем rule `reject` на `dns.google` / `cloudflare-dns.com` / `one.one.one.one`:443 — иначе fake-ip для Lagom не сработает.

## Настройки

- **Ссылки Lagom:** поле через запятую. Уход из поля пишет `dns.rules` и `route.rules` в `config.json` — **без** reload: правка домена не должна дёргать UAC и рвать связь. Работает после перезапуска подключения.
- **Локальная сеть:** тумблер переключает `inbounds[mixed-local].listen` между `127.0.0.1` и `0.0.0.0` — прокси для Quest / телефона. Пишет `config.json` и, если sing-box жив, зовёт `_reload` (UAC) — как выбор сервера, **не** как «Ссылки»: первый же пользователь включил тумблер, не перезапустил и получил в шлеме «без интернета», потому что живой sing-box так и слушал `127.0.0.1`. Правило файрвола на TCP 2080 ставит `lan.sync_firewall()` из `lifecycle.start/reload`, они и так под админом. Адрес в поле — приватный IPv4 хоста, адрес TUN `172.19.88.*` отфильтрован: вбитый в шлем, он выглядит рабочим и молча никуда не ведёт. Узкий TUN, fake-ip и WARP тумблер не трогает — устройство получает то же разделение, что ПК.
- **Пробы:** интервал проверки сервисов, пока включено. Живёт в `lagom-probe.json` рядом с config (не localStorage). Пишется на commit полей / сегмента; читается на `pywebviewready`. Нет файла — 30 с.
- **Серверы:** одна карточка. Список vless из `config.json` через `bridge.nodes()`.
  - **Подписка:** одно поле `https://…` (`lagom-sub.json`) и отдельная кнопка «стянуть список» (не ping). При открытии окна `sub_pull` (синхронно, не `_busy`) **до** авто-`start`: свежий список пишется на диск, пока TUN ещё нет — иначе панель подписки через мёртвый сервер не открывается и остаётся только убить sing-box. Кнопка питания в `_start` тоже `subscribe.refresh` до UAC. Синк не оставляет пустой селектор (sing-box: `missing tags`). Fetch с `User-Agent: Happ/1.0`, если тело не разбирается — повтор с `v2rayN/1.8.23`. Тело: URI / base64 / sing-box JSON / Clash JSON / Happ-профиль (массив полных Xray-конфигов: `protocol` + `vnext` + `realitySettings`). На каждый верхний профиль — **один** сервер: имя из `remarks` / `ps` / `name` / `meta`, хост из primary vless (`tag=proxy` или первый пригодный), не каждый balancer/`WL-*`. Плоский список outbound / sing-box / clash по-прежнему обходим целиком. Берутся только vless + Reality + tcp; vmess/trojan/ss/hy2 и Xray `security=tls` пропускаем, пачку не валим. Синк меняет только теги прошлой подписки; вручную добавленный vless остаётся. Идентичность: `uuid + host + port`. Сеть упала или 0 пригодных — старый набор не трогаем. `lifecycle.start` тянет подписку **до** `health.main`; `reload` сам не качает. Кнопка пишет файлы, живой стек не рестартит. Вставка `https://` в composer — «это ссылка подписки, поле выше». URL с токеном в установщик не попадает.
  - Выбор — выпадайка (`#sel-node`, та же семья, что комбо «Проб»): пункт auto **всегда** «Первый живой» (без `· tag` — иначе ⚡ из тега ломает строку комбо) + теги. Смена **сначала** пишет selector / `lagom-pick.json` (`select_node`), UI не откатывается из‑за `busy`. Перезапуск (`_reload`) только если sing-box уже жив и стек не занят; питание выкл — только файл. **Строки списка не кликабельны.** `refresh()` читает файл всегда: красного «жду, пока…» нет, список не запирается на reload.
  - Текущий (`n.current`, selector): имя строки `--live`, рядом беззвучный шеврон тем же штрихом, что `+` / ping. Не звезда, не лампа, не пилюля, не эмодзи. `title` строки — «сейчас через этот сервер». В auto комбо не называет текущий; в manual комбо показывает выбранный тег. Fallback: живая строка current + прежний `note()` pick vs selected.
  - Звезда → `lagom-favorite.json`, только файл, без перезапуска и без спиннера; строка красится на месте. Одна звезда, она задаёт порядок `try_order`.
  - Кнопка «обновить» справа от `+` (`#btn-node-ping`) → `health.scan_all` / `bridge.ping_nodes` фоном (не `_job`, не питание). Лампы: нет замера / выкл / мёртвый — серая `.geo-dot` `rgba(255,255,255,.18)`; живые — та же серая → `--live` по относительным ms прогона (лучший = полный cyan). `--fault` / `--lag` на точках нет. `li.on` лампу не красит. `title` точки: `142 мс` / причина. Повторный ping, пока идёт первый, — ignore. Крутится только иконка кнопки.
  - Крест → `nodes.remove` в `config.json`, без перезапуска. Удаление текущего переводит селектор на другой тег: пустой `selector` sing-box не принимает («missing tags»).
  - IP в строках не показываем — хост уже отвечает на вопрос «что это».
  - Health при старте/reload обновляет IP и выбирает первый живой, если ручной мёртв. Scan ping selector/`lagom-pick` **не** пишет. `health.main` чистит только `_probe.json`, не `_probe_2100.json` у ping.

| Файл | Что там |
|---|---|
| `config.json` vless outbounds | полные серверы |
| `lagom-nodes.json` | tag → hostname |
| `lagom-ips.json` | hostname → IP |
| `lagom-pick.json` | выбранный сервер (`manual` если вручную) |
| `lagom-favorite.json` | избранный для порядка пробы |
| `lagom-probe.json` | интервал UI-проб, секунды |
| `lagom-sub.json` | ссылка подписки и теги, которые она привезла |
| `eblit-power.json` | питание было включено (`on`) |
| `eblit-first.json` | первый экран уже прочитан (`read`) |

Порядок пробы health: избранный → last pick → порядок outbounds в config.

**Хосты резолвим системным DNS** (`socket.getaddrinfo`), не HTTP-резолвером. Раньше `resolve_one` бил в `https://dns.google/resolve` — по одному запросу на сервер, то есть 7 на каждый старт/перезапуск. Серия таких запросов с домашнего IP выглядит для Google автоматикой: в браузере на google.com появлялась reCAPTCHA «unusual traffic». Не возвращать сюда DoH.

Парсер vless: `app/web/node-parse.js`.

## Сборка / установщик

`pack.py` шлёт в payload **не** живой `config.json`. `sanitize_for_ship` выкидывает **все** vless, обходы под хосты/CIDR нод сборщика и ставит селектор на `direct`, LAN → `127.0.0.1`. Продуктовых «встроенных» серверов нет. Из `dist/Eblit` метём `lagom-*.json` / `eblit-power.json` / `eblit-first.json` / логи. Установщик не копирует `lagom-sub.json`, `eblit-power.json` и `eblit-first.json` из payload и не затирает их у пользователя. `%ProgramFiles%\Eblit\config.json` не затирает только если там уже есть нода с тегом не из утечки 1.0.0. Сток с той утечки — перезаписывает. Пустой селектор `LagomVPN` (`missing tags`) установщик чинит на месте — ставит первый vless или `direct`, ноды не сносит. Правила и домены продукта (Fastly, Lagom-суффиксы) — шлём как есть.

## Не делать

- Онскрин-лог (уже отвергнут).
- Попап с выводом `test.bat`.
- Иконки без периодической проверки — тогда они врут.
- Слать живой `config.json` в установщик мимо `sanitize_for_ship` — утекут ноды сборщика.
